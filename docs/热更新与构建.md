# 热更新与构建

[返回首页](../README.md)

本页说明当前代码的资源模式、代码加载条件与构建入口。内容依据源码核查，尚未实际构建 Player 或验证更新部署。首次打开工程请先阅读 [快速开始](快速开始.md)。

## 资源运行模式

启动时初始化 YooAsset，资源包包括 `DefaultPackage` 与 `RawFilePackage`。模式选择见 [FsmInitializeApp.cs](../Assets/Framework/Launch/FsmNode/FsmInitializeApp.cs)，资源包初始化见 [FsmInitializePackage.cs](../Assets/Framework/Launch/FsmNode/FsmInitializePackage.cs)。

资源运行模式由 `isEnablePatcher` 和运行环境共同决定：

| 环境 | 关闭更新 | 开启更新 |
| --- | --- | --- |
| Unity 编辑器 | EditorSimulateMode | HostPlayMode |
| Player | OfflinePlayMode | HostPlayMode |

本地编辑器调试使用模拟模式；离线 Player 需要准备随包资源；Host 模式需要可访问的版本服务和资源部署。版本、清单、下载及缓存清理的整体顺序见 [架构说明](架构说明.md)。

## 热更程序集加载

代码加载逻辑见 [FsmStartGame.cs](../Assets/Framework/Launch/FsmNode/FsmStartGame.cs)：

- 定义 `HybridCLR` 且非编辑器时，从资源包读取 AOT 补充元数据，并加载 `Unity.Hotfix.dll`。
- 其他情况下，使用当前已加载的 `Unity.Hotfix` 程序集。
- 加载后调用 `LccHotfix.Init.Start`，进入项目业务。

资源模式与程序集加载条件分别控制资源来源和代码加载方式。编辑器模拟运行不能验证 Player 的 AOT 元数据补充及 DLL 加载。

## 构建与部署前提

1. 按目标平台完成 HybridCLR 安装、代码与 AOT 元数据生成，确认工程使用的编译条件符合预期。具体流程参见 [HybridCLR 官方文档](https://www.hybridclr.cn/docs/intro)。
2. 项目提供 **HybridCLR → CopyAotDlls** 入口，具体复制行为见 [HybridCLRMenuItem.cs](../Assets/Editor/MenuItem/HybridCLR/HybridCLRMenuItem.cs)。该入口不能替代 HybridCLR 的完整生成流程。
3. 通过 **Lcc框架 → 工具箱 → 打包** 设置目标平台与资源版本，生成 YooAsset 资源。入口实现见 [PackEditorWindow.cs](../Assets/Editor/Editor/OdinEditorWindow/PackEditorWindow.cs)。该工具提供资源构建，应用构建使用 Unity 的 Build Settings。
4. 离线包需准备随包资源；启用联网更新时，需让版本服务、资源地址、资源版本及目标平台产物保持一致。修改配置后按 [快速开始](快速开始.md) 重新生成启动配置。
5. 在目标平台验证启动、资源加载和业务流程；启用更新时还需验证版本请求、下载与热更代码加载。

构建过程会清理相应资源输出目录，并按工具配置复制内置资源。应将自行维护的文件与构建输出区分开，具体路径与清理范围以构建入口实现为准。
