# 技能业务实现：直线射击与三连射

[战斗文档导航](../战斗系统与DSL.md) · [返回施法到清理案例](施法到清理案例.md)

本文补充 [施法到清理案例第 3 节](施法到清理案例.md#3-配置技能与子物体逻辑)，展开配置装配、系统驱动与发射节点，并将单发扩展为三连射。沿用原案例的世界、单位、表数据与资源准备；以下配置示例尚未在 Unity 中编译运行。

## 三、技能业务实现：直线射击与三连射

技能配置描述施法流程，子弹配置描述发射后的移动、碰撞和命中响应。以下示例使用项目现有接口；技能表参数填充、`HandleSubobjectHit` 等依赖仍需结合项目实现查看。

### 3.1 编写技能配置类

技能逻辑配置 ID 为 `910001`，流程为：前摇 0.2 秒 → 从 `Muzzle` 发射 → 后摇 0.1 秒。发射节点通过 `CvKey` 读取子物体配置和目标位置。

```csharp
using System.Collections.Generic;

namespace LccHotfix
{
    /// <summary>
    /// 直线射击技能配置。
    /// </summary>
    public class ShotSkillConfigs : LogicConfigBase
    {
        /// <summary>
        /// 配置前摇、发射和后摇流程。
        /// </summary>
        public ShotSkillConfigs() : base(LogicContainerKey.LogicConfigs_Skill)
        {
            DefaultLogicType = typeof(SkillLogic);

            AddConfig(910001, new List<ICustomNodeCfg>
            {
                Seq(Delay(0.2f), FighterSpawnSubobjectTo(CvKey.CV_SpawnSbjTid, CvKey.CV_TargetPos, "Muzzle"), Delay(0.1f))
            });
        }
    }
}
```

`910001` 是逻辑配置 ID，对应技能表的 `LogicID`；调用施法入口仍使用技能表 ID `900001`。`DefaultLogicType` 决定工厂创建 `SkillLogic` 根实例。

#### 3.1.1 配置与运行时实例的区别

上面的构造函数只创建配置，不直接等待或发射子弹。`Seq` 返回 `SequenceBhvCfg`，`Delay` 返回 `FTDelayBhvCfg`，`FighterSpawnSubobjectTo` 返回 `SpawnSubobjectToTargetBhvCfg`。运行时工厂根据配置的 `NodeType()` 创建对应节点：

```text
SkillLogic：本次施法的根逻辑
└─ SequenceBhv：保存当前步骤和循环状态
   ├─ FTDelayBhv：前摇 0.2 秒
   ├─ SpawnSubobjectToTargetBhv：创建子弹
   └─ FTDelayBhv：后摇 0.1 秒
```

[CustomNodeSkillExtensions](../../Assets/Hotfix/GameLogic/CoreGame/BattleKernel/LogicDsl/NodeExtensions/CustomNodeSkillExtensions.cs) 中，使用已有黑板的施法入口如下：

```csharp
public static bool CreateSkillProcess(this CustomNode self, LogicEntity entity, int skillTid, VarEnv varEnv)
{
    var creationInfo = self.GetLogicWorld().GetCreationInfo<BattleKernelCreationInfo>();
    var svc = creationInfo.CustomLogicService;
    if (varEnv == null)
        varEnv = svc.NewVarEnv();

    var firePolicy = creationInfo.SkillFirePolicy;
    if (firePolicy != null && !firePolicy.BeforeCreateSkillProcess(entity, skillTid, varEnv))
        return false;

    var skillProcess = self.CreateSkillProcessLogic(entity, skillTid, varEnv);
    if (skillProcess == null)
        return false;

    var cmd = new EntityCommand { CmdType = EntityCmdType.Nt_Skill };
    entity.SendCmd(cmd);
    entity.ReplaceComSkillProcess((uint)skillTid, skillProcess);
    firePolicy?.AfterCreateSkillProcess(entity, skillTid, varEnv);
    return true;
}
```

关键连接点是 `ReplaceComSkillProcess`：技能逻辑进入实体的组件后，实体满足技能 Group 的匹配条件，随后由系统更新。该入口需要正确的 `MainFsmGenInfo` 上下文，不能在任意普通节点上直接调用。传入已有 `VarEnv` 时，调用方还需准备本次施法需要的目标等变量；传入 `null` 只会创建空黑板，不会自动寻找目标。

#### 3.1.2 系统：推进实体持有的技能实例

[SysSkillProcess](../../Assets/Hotfix/GameLogic/CoreGame/BattleKernel/World/Systems/Behavior/SysSkillProcess.cs) 筛选拥有 `ComSkillProcess` 的实体，每次执行取得战斗 dt，结合单位的子弹时间补偿倍率，再调用 `process.Update(entityDt)`。

当 `process.CanStop()` 返回 true 时，系统按已有技能槽协议重置 CD，并移除 `ComSkillProcess`。技能实例的回收由组件移除流程负责。玩法需要持续转发世界更新，无需另外手动更新同一技能实例。

#### 3.1.3 工厂：把配置装配为运行时节点

[CustomLogicFactory](../../Assets/Hotfix/Framework/CoreGame/CustomLogic/CustomLogic.Base/CustomLogicFactory.cs) 按容器名称和配置 ID 查到配置后，调用以下重载：

```csharp
public CustomLogic CreateLogic(CustomLogicGenInfo genInfo, CustomLogicCfg config, ILogicConfigContainer cfgContainer = null)
{
    if (config == null)
    {
        CLogger.Assert(false, "CreateCustomLogic config == null");
        return null;
    }

    System.Type logicType = config.NodeType();
    CustomLogic customLogic = _nodesPool.Create<CustomLogic>(logicType);

    if (genInfo.LogicConfigID != config.ID)
    {
        CLogger.LogError($"CreateLogic: genInfo.LogicConfigID({genInfo.LogicConfigID}) != config.ID({config.ID})");
        genInfo.LogicConfigID = config.ID;
    }

    //区别于CreateCustomNode
    VarEnv varEnv = genInfo.PreEnv ?? CreatePart<VarEnv>();
    varEnv = genInfo.CopyToPreVarEnv(ref varEnv);
    CustomNodeContext context = new CustomNodeContext(genInfo, customLogic, varEnv, cfgContainer, this);
    customLogic.InitializeNode(config, context);

    return customLogic;
}
```

本例 `config.NodeType()` 返回 `SkillLogic`。工厂从池中取得根逻辑，准备黑板及共享上下文，再调用 `InitializeNode`。根逻辑的初始化继续根据子配置创建 `SequenceBhv`；顺序节点再装配前摇、发射和后摇节点。每次施法拥有各自的运行时节点状态，配置可以复用。

#### 3.1.4 顺序节点：完成前摇才执行发射

[SequenceBhv](../../Assets/Hotfix/Framework/CoreGame/CustomNodes.Foundation/BehaviorNodes/Process/SequenceBhv.cs) 将子配置装配为 `BehaviorNodeBase` 列表，保存当前步骤、剩余循环次数与循环间隔。

前摇未结束时，发射节点不会更新。前摇结束后，剩余时间片可以继续传给发射节点及后摇，因此一次世界更新可能跨过多个步骤。这里的 0.2 秒和 0.1 秒消耗的是技能收到的逻辑时间，实际时刻受世界更新和时间倍率影响。

#### 3.1.5 黑板：技能输入如何传给子弹

| 变量 | 本例用途 |
| --- | --- |
| `CV_SpawnSbjTid` | 技能表 `SubobjIds` 首项，值为子物体表 ID `920001` |
| `CV_TargetPos` | 常用施法重载从目标 View 的 `Hit` 挂点取得并保存的位置 |
| `CV_SbjTargetPos` | 发射节点写入新子物体黑板的目标位置 |
| `CV_SkillDmageRate` | 技能伤害系数，拼写沿用源码 |

发射节点创建新的子物体输入黑板。`FillSubobjectBaseVarEnv` 有选择地传递技能 ID、伤害系数和伤害类型等基础参数；自定义参数需要确认传递点，必要时通过 `WithSubobjVar` 写入。

本例 `CV_TargetPos` 保存的是位置值。三连射期间每次发射会重新读取该变量，但已有施法入口不会持续刷新它；目标移动后，后续子弹仍朝保存的位置发射。`Muzzle` 则在每次发射时从施法者 View 解析。

#### 3.1.6 发射节点：第一次更新时创建子弹

[SpawnSubobjectToTargetBhv](../../Assets/Hotfix/GameLogic/CoreGame/BattleKernel/LogicDsl/Nodes/Skill/SpawnSubobjectToTargetBhv.cs) 在首次更新的 `OnBegin` 中调用 `Spawn`。循环复用该节点时，会先重置状态，使下一轮再次进入 `OnBegin`。以下为现有实现摘录：

```csharp
protected override void OnBegin()
{
    base.OnBegin();
    Spawn();
}

private void Spawn()
{
    bool success = _cfg.TargetPos.GetVector3(this, out var targetPos, false);
    if (!success)
    {
        return;
    }

    var tid = (uint)_cfg.Tid.GetValue(this);
    var initPosSuccess = _cfg.InitPos.GetVector3(this, out var initPos);
    if (!initPosSuccess)
    {
        return;
    }

    // sunxy: 不要这样强行拉到同一水平面，还有抛物线弹道呢
    //targetPos.y = initPos.y;

    if (_cfg.InitAngle != null)
    {
        var initAngle = _cfg.InitAngle.GetValue(this);
        targetPos = RotateTargetPosition(initPos, targetPos, initAngle);
    }

    var targetEntity = EntityVarCfg.GetEntity(this, _cfg.TargetPos.VarKey, false);
    long targetEntityID = 0;
    if (targetEntity != null)
    {
        targetEntityID = targetEntity.ID;
    }


    var multiAbreastCountAdd = _cfg.MultiAbreastCount?.GetValue(this) ?? 0;
    var multiDistance = _cfg.MultiAbreastDistance;
    var count = _cfg.Count.GetValue(this);
    var angleAcc = 0f;
    if (_cfg.AngleAcc != null)
    {
        angleAcc = _cfg.AngleAcc.GetValue(this);
    }

    for (int i = 0; i < count; i++)
    {
        var dir = targetPos - initPos;

        if (multiAbreastCountAdd == 0)
        {
            var varEnv = NewSubobjVarEnv(targetPos, targetEntityID);
            var e = this.CreateSubObject(tid, initPos, varEnv);
        }
        else
        {
            // 并排多发处理
            var multiNormalDir = GetGroundSideDir(dir); // 发射方向的 XZ 横向量
            var abreastCount = multiAbreastCountAdd + 1;
            for (var n = 0; n < abreastCount; n++)
            {
                var spawnOffset = multiNormalDir * (multiDistance * ((abreastCount - 1) / 2.0f - n));
                var varEnvMulti = NewSubobjVarEnv(targetPos + spawnOffset, targetEntityID);
                var e = this.CreateSubObject(tid, initPos + spawnOffset, varEnvMulti);
            }
        }

        if (Mathf.Abs(angleAcc) > 0.0001f)
        {
            int sign = 1;
            if (_cfg.AngleSigned)
            {
                sign = count % 2 == 0 ? -1 : 1;
            }

            targetPos = RotateTargetPosition(initPos, targetPos, sign * angleAcc);
        }
    }

}

private VarEnv NewSubobjVarEnv(Vector3 targetPos, long targetEntityID)
{
    var varEnv = this.GetLogicWorld().GetCreationInfo<BattleKernelCreationInfo>().CustomLogicService.NewVarEnv();
    varEnv.WriteVar(CvKey.CV_SbjTargetPos, targetPos);
    if (targetEntityID != 0)
    {
        varEnv.WriteVar<long>(CvKey.CV_TargetEid, targetEntityID);
    }

    if (_cfg.SubobjVarInitFuc != null)
    {
        _cfg.SubobjVarInitFuc(this, varEnv);
    }

    return varEnv;
}


public Vector3 RotateTargetPosition(Vector3 initPos, Vector3 targetPos, float angle)
{
    // 计算从initPos指向targetPos的方向向量
    Vector3 dir = targetPos - initPos;
    // 创建围绕Y轴（Vector3.up）旋转的四元数
    Quaternion rotation = Quaternion.AngleAxis(angle, Vector3.up);
    // 旋转方向向量
    Vector3 rotatedDir = rotation * dir;
    // 计算新的目标位置
    Vector3 newTargetPos = initPos + rotatedDir;

    return newTargetPos;
}

private static Vector3 GetGroundSideDir(Vector3 dir)
{
    var forward = new Vector3(dir.x, 0f, dir.z);
    if (forward.sqrMagnitude < 0.0001f)
    {
        forward = Vector3.forward;
    }

    return Vector3.Cross(Vector3.up, forward.normalized).normalized;
}
```

目标位置或起始位置解析失败时，发射方法直接返回。因此“技能实例已创建”不能证明子弹已生成，排查时应先确认黑板和 View 挂点。

`Count` 控制一次 `Spawn` 中创建的数量；并排和角度参数也在本次调用内处理。它们没有逐发等待时间。需要按时间间隔发射三次时，使用第 3.5 节的 `LoopSeq`。

### 3.2 子物体配置：移动、碰撞与命中响应

沿用原案例的 `ExampleProjectileConfigs(930001, hitFxPath)`，其根类型是 `SubobjectLogic`，根节点列表包含：

| 配置 | 职责与执行时机 |
| --- | --- |
| `Subobject_SetLocomotionStraightDir(10f)` | 初始化时设置直线位移、速度和朝向，默认按 XZ 平面处理方向 |
| `Subobject_InitColliderByPbCfg()` | 首次更新时按子物体表初始化 Bounds、碰撞器和相关变量 |
| `HandleSubobjectHit(hitFxPath)` | 常驻命令处理节点，收到命中命令后处理表现、伤害和命中寿命 |

这里不包 `Seq`：命中处理节点属于 `CustomNode` 命令处理节点，不能放进要求 `BehaviorNodeBase` 的顺序队列。完整配置类见 [原案例第 3 节](施法到清理案例.md#3-配置技能与子物体逻辑)。

### 3.3 注册配置并连接表数据

在玩法注册器已有的 `Register(ICustomLogicService service)` 方法中，将本页技能配置与原案例子物体配置注册到对应容器：

```csharp
service.AddConfigContainer(new ShotSkillConfigs());
service.AddConfigContainer(new ExampleProjectileConfigs(930001, "Example/HitFx"));
```

`Example/HitFx` 必须替换为实际资源地址。`ShotSkillConfigs` 替代原案例的 `ExampleShotConfigs`；每个容器名称只能注册一次，已有正式容器时将配置加入原容器。

```text
技能表 900001
  → LogicID = 910001 → ShotSkillConfigs 中的技能逻辑
  → SubobjIds[0] = 920001 → 子物体表
      → LogicID = 930001 → ExampleProjectileConfigs 中的子物体逻辑
```

单发与三连射可通过替换 `910001` 的节点组合分别验证。若需要同时保留两种技能，应使用不冲突的逻辑配置 ID，并准备对应的技能表映射。

### 3.4 命中与清理：技能和子弹分别结束

技能完成后摇即可结束，不等待子弹命中。子弹由自己的碰撞、命中次数和寿命控制结束；技能结束后，已经生成的子弹仍可继续飞行。

本例沿用 `MaxHitCount = 1`、`SingleHitCount = 1`、`HitWithLife = true`、`During = 3` 的子物体表设置，每发子弹各自保存命中与寿命状态。有效命中后是否实际扣血，仍取决于伤害流程中的免疫、闪避等规则。

完整碰撞命令、伤害及清理链路见 [原案例第 6～8 节](施法到清理案例.md#6-命中从碰撞到-dsl-命令节点)。

### 3.5 扩展为三连射

将 `AddConfig(910001, ...)` 中原来的 `Seq` 替换为以下组合，配置 3 次发射、0.1 秒间隔，前摇和后摇继续保留。子弹移动、命中和伤害处理沿用原有配置：

```csharp
Seq(
    Delay(0.2f),
    LoopSeq(new List<ICustomNodeCfg>
    {
        FighterSpawnSubobjectTo(CvKey.CV_SpawnSbjTid, CvKey.CV_TargetPos, "Muzzle")
    }, 3, 0.1f),
    Delay(0.1f))
```

当前 `SequenceBhv` 只有在一轮结束后仍有剩余轮次，或处于无限循环时，才设置 `_remainTimeToNextLoop`。第三轮结束后不会追加循环间隔，直接进入外层后摇。

在正常推进且无打断的情况下，按技能累计收到的逻辑时间，名义时序如下；实际发生时刻受更新步长和浮点误差影响，较大的 dt 可能让多次发射落在同一次世界更新中。

| 累计逻辑时间 | 行为 |
| --- | --- |
| 约 0.2 秒 | 前摇结束，发射第 1 发 |
| 约 0.3 秒 | 发射第 2 发 |
| 约 0.4 秒 | 发射第 3 发，进入后摇 |
| 约 0.5 秒 | 后摇结束，技能可停止 |

验证时只触发一次施法：前摇期间无子弹，之后总共生成三发；每发各自命中或寿命结束后清理；技能后摇完成后移除 `ComSkillProcess`。再次施法应重新经历前摇和三次发射，不能残留上一轮计时或命中次数。世界、资源及边界验收继续使用 [原案例的验证清单](施法到清理案例.md#9-如何逐段验证)。
