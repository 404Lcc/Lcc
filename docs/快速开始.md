# 快速开始

[返回首页](../README.md)

本文介绍当前完整工程的本地编辑器启动方式。步骤依据源码和配置整理，尚未通过实际 Play Mode 验证。

## 开发环境

- Unity **2023.2.20f1**，以 [ProjectVersion.txt](../ProjectSettings/ProjectVersion.txt) 为准。
- URP **16.0.6**、Input System **1.7.0**、YooAsset **2.3.14**。
- HybridCLR、Luban、LitMotion、NavMeshPlus 通过 Git 包引用，完整依赖见 [Packages/manifest.json](../Packages/manifest.json)。首次打开需要能够访问对应 Git 仓库与 OpenUPM 源。
- 数据表导出工具使用 **.NET 8** 运行时；仅运行 Unity 项目时不需要执行导表脚本。

当前仓库按完整 Unity 工程打开。根目录 `package.json` 仍保留旧版 Unity / ILRuntime 声明，不能作为当前工程的安装与兼容性依据。

## 准备本地配置

1. 使用 Unity **2023.2.20f1** 打开仓库根目录，等待包依赖恢复与脚本编译完成。
2. 检查 [GameConfig_Version.txt](../Assets/GameConfig/GameConfig_Version.txt)。本地编辑器调试可保持 `isEnablePatcher` 为 `false`，启动将使用 YooAsset 编辑器模拟模式。
3. 修改配置后，打开 **Lcc框架 → 工具箱 → 框架配置**，点击 **加密GameConfig**。该操作生成启动时读取的 `Assets/Resources/GameConfig_Build.txt` 和 `Assets/Resources/GameConfig_Version.txt`。

启用更新时，需要按自己的环境配置版本服务与资源地址。配置文件中的本机路径不可直接用于其他机器；资源模式和构建说明见 [热更新与构建](热更新与构建.md)。

## 启动工程

打开 [Launch.unity](../Assets/Scenes/Launch.unity)，进入 Play Mode。当前 Build Settings 也以此场景为入口。

启动会加载当前项目的配置、引导和界面等资源，需要保留相应资源及 YooAsset 收集配置。编辑器模拟运行不需要先构建 Player 资源包，但仍依赖项目资源能被正确收集和加载。

需要了解启动过程时，阅读 [架构说明](架构说明.md)。编辑器运行成功后，仍需单独验证目标平台的 Player 和热更新流程。

## 从哪里开始修改

- [Init.cs](../Assets/Hotfix/GameLogic/Init/Init.cs)：热更业务入口，创建 `GameMain`。
- [GameMain.cs](../Assets/Hotfix/GameLogic/Package/GameMain/GameMain.cs)：模块注册、服务实现配置及初始化。
- `Assets/Hotfix/GameLogic`：当前项目的流程、模块、界面和玩法。

先从现有业务如何使用框架开始阅读，再按需要替换服务和资源。完整目录与战斗扩展入口见 [架构说明](架构说明.md)，导表和协议操作见 [开发工具](开发工具.md)。
